## Implications from the search (abstract-level)

1. **Novelty must be narrowed.** "Calibrated model cascade" for NLU exists: C3 (cross-lingual, calibration before cascade) and CascadeBERT (calibrated complete-model cascade). Kestrel may only claim what the comparison table below supports, using the Ch. 5.4 wording ladder.
2. **Tier-4 confidence should come from label probabilities, not the model's own stated (verbalized) confidence.** shen2026certified shows temperature scaling cannot repair verbalized confidence that stays above 0.5 while accuracy falls. This matches the blueprint's constrained-decoding approach (Ch. 11.1).
3. **Safety: Gemma-4-E2B.** kasnesis2026callsite reports it actuated on 87.2% of requests for devices the site does not own. Tool calls must stay allowlisted and validated (Ch. 15), and wrong-target requests belong in Kestrel-Tasks-v0.
4. **Model calibration differs per SLM.** chuang2025ondevice reports that *raw* uncertainty distributions depend more on the SLM and the uncertainty method than on the data, so each tier needs its own calibration. Whether thresholds can then be shared is open: zhang2026cauc (full text) shows that after per-model temperature scaling one shared threshold works across 3B–31B LLMs and image models, and bounds its regret by the calibration error. Per-tier thresholds (R3) are not obviously better; see proposed D9.
5. **Hinglish data:** there's no public Hinglish *intent* benchmark among the hits. MASSIVE has hi-IN, but it's translated, not code-mixed. CST5 (agarwal2022cst5) and code-switching augmentation (krishnan2021mcs) are routes to generating Hinglish items for Kestrel-Intents-v0, which still needs human checking.

**Reading (updated 2026-10-17 after full texts of all seven † rows, rounds 4–6):** no single prior work matches every column, but each planned difference has close prior work on its own:
- *Calibrated cascade with validation-chosen thresholds:* C3, CascadeBERT and especially **zhang2026cauc**. CAUC-RF already does what R3 plans in outline: calibrate each model, then pick a stopping threshold on a separate validation set under a budget. It also proves that a calibrated threshold bounds accepted accuracy (Prop. 1). RQ2 is a **replication in Kestrel's setting**, not a new idea.
- *Encoder → LLM routing for intent detection with latency gains:* **arora2024intentllm**. Full text: the routing signal is uncalibrated MC-dropout disagreement, the LLMs are cloud APIs, and the results are best validation-set scores. Kestrel's Tier 3 → Tier 4 path is close in shape but differs in signal (calibrated), location (local CPU) and evaluation (frozen test sets).
- *A deterministic tier before a model:* **sadhu2026neurosymbolic** (Raspberry Pi, latency and energy) and mane2026cascadens. Full text: sadhu's router assigns categories before inference; it never escalates on low confidence, and its one calibration attempt had no effect.
- *On-device resource measurement:* sadhu2026neurosymbolic, alkiek2026harissa, chaganti2026ondevicener, kag2023edgeselective (edge → cloud).

What the full texts add:
- **Cost is rarely measured on hardware.** CAUC uses parameter counts, C3 and CascadeBERT use FLOPs, arora2024 uses cloud API latency, and chuang2025 emulates "on-device" on A100s. Among the full texts, only sadhu2026 and chaganti2026 measure on a device, and neither has a calibrated multi-tier cascade (alkiek2026harissa and kag2023edgeselective also measure on devices, per their abstracts).
- **The tiers in prior calibrated cascades are all the same kind:** every model emits logits over the same candidate set. None mixes a rule tier that may abstain, a classifier head and a generative model whose confidence comes from constrained label decoding.
- **Baselines:** wang2026misguided finds that no commercial router beats random routing between two well-chosen models at matched cost, and chaganti2026 also reports a cost-matched random baseline. The PREREG has none (proposed D10).
- **Language disparity is named but untested:** the TMLR routing survey (moslem2026routingsurvey, ethics section) warns that cost-optimized routing can give under-represented languages and non-standard writing worse quality *and* a higher routing cost. jitkrittum2023deferral shows that confidence-based deferral is weakest under distribution shift. Both make RQ7 sharper (proposed D11).

What still differs, as a **combination** (Ch. 4.5: don't claim novelty because components are combined):
- a calibrated cascade over **heterogeneous tier types** (rules that may abstain → frozen encoder + linear head → local generative SLM with constrained label decoding) **for intent routing with OOS**, measured end to end on a commodity x86 CPU (latency + peak RSS) instead of FLOPs or parameter counts;
- **code-mixed Hinglish**: no cascade, routing or calibration study in the search evaluates code-mixed input (RQ7). This is still the most distinctive part.

Wording: "we *evaluate* …" / "we *replicate* … on-device". Claims of the form "no prior work in our search reports …" are only for the Hinglish cascade/calibration evaluation, and only after the stop rule is met. **Framing (human, 2026-10-17):** a measured evaluation study; the calibrated cascade is not claimed as new; the code-mixed Hinglish evaluation is the distinctive part.
