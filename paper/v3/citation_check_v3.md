The expected metadata in the request (titles, authors, years, venues) was correct for all six. No field had to change. The differences below are about names, spellings and the claim wording.

### Draft wording to fix (kestrel_v3.tex, read only, not edited)

1. **austin2021mbpp, line 120**: "HumanEval and MBPP judge generated Python by hidden tests". This is wrong for MBPP. Its prompts show the tests the output is checked against (Sec. 4.2): "The example prompt in Figure 1 shows all three of the test assertions that the model output will be checked against." It is right for HumanEval. Codex builds the HumanEval prompt from "a header, a signature, and a docstring" (Sec. 3.2), and the unit tests are not in the prompt, although that paper never uses the word "hidden". Suggested wording: "judge generated Python by running it against unit tests". If the "hidden" contrast matters, say it of HumanEval only.
2. **austin2021mbpp, size**: if the paper gives a size, the exact number is **974** problems. "About 1,000" is acceptable. The paper describes them as "a large set of crowd-sourced questions and a smaller set of questions edited and hand-verified by the authors", so not all of them are crowd-sourced. Each problem has **three** test cases.

### Smaller differences (status stays OK)

- **chen2021codex, pass@k**: the Codex paper does not introduce pass@k. It credits the metric to Kulal et al. (2019) and adds an unbiased estimator of it (n = 200 samples, k <= 100). "Measures functional correctness with unit tests (pass@k)" is accurate. Do not write "introduces pass@k".
- **chen2024selfdebug, name spelling**: the camera-ready PDF and arXiv print "Nathanael Schärli". The ICLR site, its proceedings BibTeX and its JSON data spell it "Schaerli". The bib uses the PDF spelling, `Sch{\"a}rli`. The venue is ICLR 2024 (poster, OpenReview KuPixIqPiq), and proceedings.iclr.cc gives pp. 8746-8825. The OpenReview page itself showed a bot check, so the OpenReview id was taken from the ICLR accepted-paper data.
- **chen2024selfdebug, abstract wording**: the ICLR proceedings page abstract says "by leveraging code execution". The camera-ready PDF and arXiv v2 say "by investigating the execution results". The quote below is from the PDF.
- **rajpurkar2018squad2, dataset name**: the published ACL version calls the dataset **SQuADRUn** in its abstract and text, and says (Sec. 1) "designate it SQuAD 2.0 on the official SQuAD leaderboard". arXiv v1 uses "SQuAD 2.0" throughout. The draft's "SQuAD 2.0" is fine. It is a Short Paper (Volume 2), pp. 784-789.
- **wilson1927, author and access**: Crossref names the author "Edwin B." Wilson; the request had "E. B. Wilson", the same person. Taylor & Francis returned a Cloudflare 403 and JSTOR showed a client challenge, so the publisher page could not be opened. Vol. 22, no. 158, pp. 209-212, June 1927 and DOI 10.1080/01621459.1927.10502953 come from the publisher's own Crossref deposit (Informa UK Limited). Three other sources agree: doi.org resolves the DOI to tandfonline.com; the JSTOR DOI 10.2307/2276774 redirects to the same DOI; and OpenAlex holds the T&F citation string "Journal of the American Statistical Association: Vol. 22, No. 158, pp. 209-212". OpenAlex's own biblio says last page 209, which is an aggregator error. OpenAlex marks the article closed access with no repository full text, so the claim could not be checked in Wilson's text. The attribution is supported by a secondary source, Cousins, Hymes & Tucker (quoted in the table).
- **bubblewrap**: the official one-line description on GitHub is "Low-level unprivileged sandboxing tool used by Flatpak and similar projects". It does not mention namespaces. The namespace part comes from the README ("Bubblewrap uses these [user namespaces] to build the sandbox") and the repository topics (`linux-containers`, `user-namespaces`).
- **No published version** of chen2021codex or austin2021mbpp turned up in a Crossref title search on 2026-10-28. Both stay `@misc` arXiv entries. NeurIPS 2020 and ICLR 2024 list no DOI for lewis2020rag or chen2024selfdebug, so those entries carry the proceedings URL and the arXiv id.
